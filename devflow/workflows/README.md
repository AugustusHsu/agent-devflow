# devflow/workflows — 跨職位交接索引

本層只做導航：按時間順序指出一張單從準備到收尾，各階段適用哪幾條規則、由誰接手、交付落在哪、何時停下回報。
規則本體只有 `../WORKFLOW.md`（規則帶 ID），職位的職責本體在 `../seats/`，工具側的指令與實測值住 `../forges/`、`../coders/`、`../orchestrators/` 各對照表。
本檔不定義規則、不綁工具、不是對照表：每一格都只引用上述三處已有的條文與落點，不新增義務、不新增判準；與條文牴觸時以條文為準。
行為人兩欄的分野只及於**執行位自身的職責**——建 worktree、啟動實作位、派審、準備階段等，列舉見 `../seats/manager.md` 的「職責」與「填充者」兩段：`devflow.yml` 的 `seats.manager` 已綁定時由執行位執行，省略綁定時這些職責歸協調位（`I2`、`L2`、`R1`）。表中已標為協調位的格（開單、收尾）是協調位固有的職責，不隨 `seats.manager` 改變；以 `M2` 或 `I9` 指路的格（合併、阻擋項處置）的行為人也不由綁定推導，依該條與 `devflow.yml` 的設定。

## 單線交接表

| 階段 | 規則 | 行為人（已綁定 manager） | 行為人（未綁定） | 交付落點 | 停下／回報出口 |
|---|---|---|---|---|---|
| 0 準備 | `L7` | 執行位（受協調位以 issue 留言委託） | 協調位自做 | issue 上標明「準備材料」的留言、`.hermes/plans/` 之下的材料檔（`L7`） | 委託七欄缺一即回報缺欄並停（`L7`） |
| 1 開單與 T | `L1` `G1` | 協調位固定 G 並確認 `L1` 齊備；T 由執行位撰 | 協調位 | issue body 的 `L1` 各欄，其中基準欄記 G（`G1`）與 T 的識別——T 取規格檔 `@ commit`，或治理／流程類的本 issue 留言 id，兩種形狀見 `../templates/issue.md` | 「未決事項」非空即不派工（`L1`） |
| 2 建 worktree | `I1` `I2` `L2` | 執行位建 | 協調位建 | 分支 `<N>-<slug>` 與 `../<repo>.worktrees/<N>`（`I1`、`I2`） | — |
| 3 派實作 | `L2` `L3` `I1` | 執行位派 | 協調位派 | 派工交付 issue、G、T、worktree 路徑、驗證指令（`L2`）；產出落在 worktree 內的 commit | 遇未決事項依 `L3` 兩路徑：命中停判準者 issue 留言後停、協調位問人；未命中者為工程判斷，issue 留言記錄情況、暫定處置、位置後續行 |
| 4 複驗與 PR | `L4` `R6` `G5` | 執行位複驗並開 PR | 協調位 | PR，引用 issue、G、T、head sha（`L4`） | 測試未綠即不 push、不開 PR（`L4`） |
| 5 派審 | `R1` `R2` `R4` `R12` | 執行位派審 | 協調位派審 | 丟棄式 checkout 內的審查、verdict 留言（`R5`、`R12`） | head 變更即 verdict 失效、重審（`R3`） |
| 6 阻擋項處置 | `R11` `R13` `I9` `I10` | 依 `I9` 查 `autonomy` 檔位 | 依 `I9` 查 `autonomy` 檔位 | PR 上的處置留言，URL 記入 issue 的「審查處置」段（`R11`） | 續審、升人或擱置的分類依 `R13` |
| 7 合併 | `M1` `M2` `I3` | 合併者依 `devflow.yml` 的 `merge` 設定（`M2`）；執行位只核對並回報 `M1` 三項前提，不自行合併 | 合併者同依 `M2` 與 `merge` 設定，不隨 `seats.manager` 改變：`human` 由人按，`orchestrator` 僅在有機械 guard 能驗 `M1` 時才按 | merge commit，訊息帶 PR 號、reviewer、head sha（`I3`、`R5`） | 前提 `M1` 任一不成立即不按；main 前進時 merge main、重測、重審（`M3`、`M4`） |
| 8 收尾 | `C1` `C2` `C3` `C5` | 協調位 | 協調位 | issue 關閉並讀回（`C2`）、分支與 worktree 清除、本單專屬子目錄不存在（`C1`、`C5`） | 任一步判準未成立即收尾未完成，補做依 `F4` |

表內的 ID 指向 `../WORKFLOW.md` 的同號條文，行為人指向 `../seats/` 的同名職位檔；某格與該條文讀起來不一致時，依條文，並把差異回報到該單的 issue。

## 阻擋項處置與 autonomy 的分支（只指路）

`autonomy` 鍵的三個檔位與未設時的預設見 `I8`；三檔的差異只在「誰處置審查阻擋項」與「誰按合併」兩件事，見 `I9`。
阻擋項出現時的查法：先依 `I10` 判機械類或方向類，再依 `I9` 定該檔位下的行為人，處置在 PR 留言標 `FIX`／`DEFER`／`REJECT` 並附依據（`R11`），下一輪是續審、升人或擱置則依 `R13` 判定。
合併者不由本檔也不由 `autonomy` 單獨決定，依 `M2` 與 `devflow.yml` 的 `merge` 設定；不受 `autonomy` 影響、一律由人處置的事項列舉在 `I11`。
三檔各自的權限分配只住 `I8`～`I11` 一處，本節不複述，也不在此放寬或收緊。
