# seat: implementer（實作位）

職位定義。只寫這個位要做什麼、受哪些規則約束、填它的人或工具要會什麼。不指定填哪個工具，也不記工具的指令；前者是綁定、後者住對照表。

## 職責

- 在指定的 worktree 內，依 issue 上寫的 G、T、AC 與 write scope 完成實作（`L2`）；同一時間只為一張 issue、一條分支、一個 worktree 工作（`I1`）。
- 遇未決事項依 `L3` 分兩路徑：命中停的判準即 issue 留言後停；未命中者為工程判斷，issue 留言記錄情況、暫定處置、位置後繼續。不猜。
- 完成：測試綠 → push 分支 → 開 PR，引用 issue、G、T、head sha（`L4`）；進 main 一律經 PR、以 merge commit 合入（`I3`）。push 與開 PR 可由本位或協調位執行，`L4` 只定義結果。
- 審查未過（`F1`）：在同一 issue 修正；head 變更後原 verdict 失效，重新受審（`R3`）。
- main 前進造成衝突：後合者把 main 併進自己的分支，重測、重審（`M3`、`P3`）。
- 治理變更（規則本體、模板、對照表、skill）也是實作，同樣經 PR、依舊 G 受審（`G2`）；新規則要求的檢查器尚不存在時，先做成「建議」（`G4`）。

## 產出物

分支上的 commit、PR、issue 留言（`L3` 的持久紀錄）。產出物屬下列類型時，各依其規則：

- 對照表格子：狀態欄三值、值欄與狀態的對應、驗證方式與受測環境依 `R7`、`R8`、`R9`、`R10`。
- 規格文檔：位置與格式依 `S1`，經 PR 合入（`S2`）；版本欄四碼（`V1`），適用對象依 `V4`。
- 文檔投影：一個來源、兩種投影，規範只有一份（`D1`）；入口檔只擁有 devflow 區塊、內容以模板為準（`D2`）；人類站依 `devflow.yml` 的 `docs` 設定（`D3`）。

## 禁止

- 不在主 checkout 工作；不自建 worktree，只收路徑（`I2`）。
- 不動 write scope 外的東西、不改 issue 明列的 AC（`L3`）。
- 工作區內出現非本任務產生的檔案或工具生成物：回報，不自行納入版控、不自行刪除（`L3`）。
- 不對自己的工作簽正式 verdict（`R1`）。
- 不自行 bypass（`F3`、`B1`）。
- repo 內不放工單檔、BACKLOG、審查報告副本（`I4`）；產物不手抄、不設同步戳記（`I5`）。
- 超過 20 KB 的檔案不整份載入（`D4`）。

## context 語意

延續：同一任務內跨輪保留脈絡——修正輪（`F1`）、中斷後續接。

## 規則義務

`I1`、`I2`、`I3`、`I4`、`I5`、`L2`、`L3`、`L4`、`R1`、`R3`、`R7`、`R8`、`R9`、`R10`、`M3`、`F1`、`F3`、`G2`、`G4`、`B1`、`P3`、`S1`、`S2`、`V1`、`V4`、`D1`、`D2`、`D3`、`D4`。

## 填充者須具備的能力

- 在給定路徑的 worktree 內工作；不需要、也不得自己建 worktree。
- 執行 issue 上的驗證指令與測試。
- 在 forge 的 issue 上留言（`L3` 的通道），停下時能以可辨識的方式回報 blocked。
- 提交變更成 commit。push 與開 PR 若由本位執行，須具備對應的 forge 權限。
- 中斷後能續接同一脈絡（context 語意）。
