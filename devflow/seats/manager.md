# seat: manager（執行位）

職位定義。只寫這個位要做什麼、受哪些規則約束、填它的人或工具要會什麼。不指定填哪個工具，也不記工具的指令；前者是綁定、後者住對照表。

## 職責

單一 issue 的執行負責人：撰 T、派實作位、複驗、開 PR、派審、處置阻擋項、回報協調位。

- 撰 T：依協調位固定的 G 與 issue 的 `L1` 各欄撰寫，含逐條 AC、write scope、驗證指令；AC 的鑑別力依 `L1`——對至少一個明確的未達成候選實跑同一步驟並得到不同輸出；證據須能定位，計數式斷言不得作為任一條 AC 的唯一證據（`R6`）。
- 派實作位：建 worktree 於 `../<repo>.worktrees/<N>`，實作位不在主 checkout 工作（`I2`）；交付 issue、G、T、worktree 路徑、驗證指令（`L2`）；同一時間一張 issue 只有一個實作者（`I1`）。
- 實作位停下時依 `L3` 判停或續；命中 `L3` 的停判準（處置落在 write scope 外、或 issue 與規格、留言互相矛盾）則回報協調位，不自行決定方向。
- 複驗與開 PR：複驗以可重跑且具鑑別力的指令為準（`R6`）；測試綠後 push 分支、開 PR 並引用 issue、G、T、head sha（`L4`）；PR 記錄本任務的 G 並依 G 審查（`G1`）；候選分支中的入口檔、skill、CI 變更不當本次治理依據（`G5`）。
- 派審查位：依 `R2` 的填位基準與 `devflow.yml` 的綁定派審（`R1`、`R2`、`R12`）；餵入 `templates/review-prompt.md` 全文（`R4`）。**派審是本位的職責，不是協調位的。** `R12` 的沙箱設定、可寫根實際值，以及該輪結束前的三項核對——checkout 的 HEAD 等於被審 sha、該輪工具日誌顯示的核准政策為「不得自行升權」、該 checkout 的 `git diff` 已另存——由本位負責並記入 verdict 留言。
- head 變更即 verdict 失效，重派審（`R3`）。
- 處置阻擋項：依 `I10` 的三項判準判機械類或方向類。機械類在 `autonomy` 為 `assisted` 或 `auto` 時由本位自決，並依 `R11` 標 `FIX` 附可重跑的複驗；方向類與 `R13` 的升人、擱置兩款一律回報協調位（`I9`）。
- 回報協調位：`APPROVE` 後附 `M1` 三項前提的核對結果；不自行合併（`M2`）。
- 失敗處置：填充者不可用（配額耗盡、provider 錯誤）時停下回報，不自行更換綁定（`I7`）。

## 產出物

issue 上的 T 與派工紀錄（`L1`）、分支與 worktree、push 與 PR（`L4`）、派審的 verdict 留言與其沙箱記載（`R12`）、阻擋項的處置留言（`R11`）、回報協調位的 `M1` 核對結果。

## 禁止

- 不自行合併，也不放行未達 `M1` 的合併（`M2`）。
- 不代簽 verdict——審查由審查位以全新 context 做（`R1`）；head 變更後的舊 verdict 不得續用（`R3`）。
- 方向類阻擋項不自行處置；`R13` 的升人與擱置不自行裁決（`I9`、`R13`）。
- 不改 issue 明列的 AC 與 write scope；需要改即回報協調位（`L3`）。
- 不自行更換填充者綁定，也不新增 `devflow.yml` 未宣告的綁定候選（`I7`）。
- 超過 20 KB 的檔案不整份載入（`D4`）。

## context 語意

一張 issue 一位：同一張單的多輪派工續接同一個 context，不跨任務續用。規則版本在任務邊界固定於該單的 G，進行中的任務續用舊 G（`G1`、`G3`）。

## 規則義務

`I1`、`I2`、`I6`、`I7`、`I9`、`I10`、`L1`、`L2`、`L3`、`L4`、`R1`、`R2`、`R3`、`R4`、`R6`、`R11`、`R12`、`R13`、`M1`、`M2`、`G1`、`G3`、`G5`、`D4`。

## 填充者

工具或人。綁定寫在 `devflow.yml` 的 `seats.manager`（`filler`／`launch`／`instance`／`model`），`launch` 的語意見 `seats/README.md`。**省略 `manager` 綁定時，本位的職責歸協調位**——與沒有本位的既有形狀相同，issue、分支、worktree、PR 的形狀不因此改變；換填充者同樣不改變這四者的形狀（`I6`）。

## 填充者須具備的能力

- 撰 T 並寫回 forge：開、讀、留言 issue；開 PR、讀回 PR 狀態與 CI 結果（`L1`、`L4`）。
- 建與移除 worktree、判定 commit 間的祖先關係（`I2`）。
- 啟動與停止實作位的填充者，並能判定它已停（`L2`）。
- 在丟棄式 checkout 內啟動審查位的填充者，設得起「不得自行升權」與可寫根收斂，並核對該輪三項（`R12`）；餵入 `templates/review-prompt.md` 全文（`R4`）。
- 實跑驗證指令並貼出輸出原文，不以「通過」等結論代替（`L1`、`R6`）。
- 判定阻擋項的類別並標處置（`I10`、`R11`）。
