# seat: approver（裁決位）

職位定義。只寫這個位要做什麼、受哪些規則約束、填它的人或工具要會什麼。不指定填哪個工具，也不記工具的指令；前者是綁定、後者住對照表。

## 職責

流程自己不能做的決定由此位做，並寫回 forge 成為持久紀錄：

- 按合併（第 6 節）：前提 `M1` 全部成立才按；合併者依 `devflow.yml` 的 `merge`（`M2`）；以 merge commit 合入，不 squash、不 rebase merge（`I3`）；merge commit 訊息帶 PR 號、reviewer、head sha（`R5`）；多張任務時合併序列化（`P3`）。撤回壞實作的 revert PR 同樣經此合入（`F5`）。
- 授權 bypass（第 10 節）：直推 main 需當次授權，不是常設許可（`B1`）；被授權的 commit 須引用帶 `bypass` label 的 issue（`B2`）；stage 0 期間不需 bypass issue（`B4`）。
- 未決事項：實作位停下、協調位提問後，答案連同依據寫回 issue（`L3`）。
- 取消任務時保留或丟棄（`L6`）；兩輪無進展的升級（`F1`）；T 的修訂方向（`F2`）。
- 規則變更：issue 記錄問題與裁決，裁決＝選定唯一處置（`G2`）；新規則的檢查器升為必需關卡，須工具可執行且正反測試通過（`G4`）。
- 規格（第 2 節生效時）：規格 PR 由人審、依 `merge` 設定合併（`S5`）；規格變更經 PR 合入，版本＝該 merge commit（`S2`）；「未決事項」非空的規格不得核准（`S6`）。
- stage 只標示已驗證的能力；降 stage 不放寬 main 保護、憑證或發布授權（`ST4`）。

## 產出物

issue 留言上的裁決（含依據）、merge 動作、`bypass` issue 與當次授權。

## 禁止

- 裁決不寫回 issue 不算數——留言是持久紀錄，提問通道只是通道（`L3`）。
- 升級不等於放行（`F1`）。
- bypass 不是常設許可（`B1`）；降 stage 不放寬 main 保護、憑證或發布授權（`ST4`）。
- 對規則變更的裁決不取代審查位的審查；候選版本不得放寬對自己的審查（`G2`）。

## context 語意

不適用：裁決以 issue 留言為單位，各自獨立。

## 規則義務

`I3`、`L3`、`L6`、`R5`、`M1`、`M2`、`F1`、`F2`、`F5`、`G2`、`G4`、`B1`、`B2`、`B4`、`S2`、`S5`、`S6`、`ST4`、`P3`。

## 填充者

人。`M2` 允許非人合併者在有機械 guard 能驗 `M1` 時按合併，那只是合併這一項的代行；其餘裁決歸人。

## 填充者須具備的能力

- forge 上的合併權限與 issue 留言權限。
- 授權 bypass 的權限：main 保護的例外由此位掌握。
- 對規則變更做出裁決，並寫明依據。
