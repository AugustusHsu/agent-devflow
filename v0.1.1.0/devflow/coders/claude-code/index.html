coder: claude-code¶

衍生值對照表，只有通用節（值欄宣稱可重用的工具能力或程序，repo 與環境只是可替換的參數）。本機節——具名的環境 instance——住 devflow.local/<同路徑>，不隨 kit 安裝。分節與狀態欄依 R9。

通用¶

面向 職位 值 狀態
headless 執行（L2） implementer 在 worktree 內：claude -p "<prompt>" --output-format json --max-turns <N>；stdout 為單一 JSON ✅ 可用（實測 2026-09-20，驗證方式：在既有 worktree 內執行 claude -p "<任意 prompt>" --output-format json --max-turns <N>，stdout 為單一 JSON 物件，含 session_id（字串）、num_turns（數字）、result（字串，最終回覆全文）三個鍵；此程序不依賴任何特定 prompt 或 repo，第三者現在可獨立重跑。實跑（forge 上可定位的 2.1.277 派工紀錄，一處）：#114 第一段派工——orchestrator 留言貼出該次 stdout JSON 的 session_id、permission_denials 4 筆、--allowedTools 完整名單，受測環境明記 Claude Code 2.1.277（https://github.com/AugustusHsu/agent-devflow/issues/114#issuecomment-5748688404 ）。其餘同期派工的指令與版本未留存於 forge，不作本格證據。受測環境：2026-09-20，Claude Code 2.1.277 headless（實作位當日在同一台主機執行 claude --version，stdout 為 2.1.277 (Claude Code)，與本表本機節「版本」格一致），權限為 --allowedTools 白名單、未用 --dangerously-skip-permissions，執行身分為本機使用者以 Anthropic 訂閱登入，目標 repo AugustusHsu/agent-devflow；證據：https://github.com/AugustusHsu/agent-devflow/issues/114#issuecomment-5748688404（含 session_id、permission_denials，即該次 stdout JSON 摘錄）。前次受測環境為 2026-09-11、Claude Code 2.1.267 headless，證據：issue #4 留言 https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5622874599 。本格受測環境原記 2.1.267，#114 提報本機已升 2.1.277，依 R10 由 #120 重驗更新——2.1.277 上已有上列實跑，狀態維持 ✅）
入口檔（D2） — CLAUDE.md ⬜ 未測
權限：--allowedTools — --allowedTools '<pattern list>' 白名單，但不是唯一的放行機制：唯讀且在工作目錄範圍內的指令（如 ls、echo）另有自動放行途徑，名單外也會過；名單外且不符該途徑的呼叫（如 python3、寫工作目錄外、; 串接的複合指令）被拒，記入 stdout JSON 頂層的 permission_denials（每筆含 tool_name、tool_input） 📝 已宣稱（R9 子類「驗證未達 ✅」：本格附有第三者現在能執行的驗證方式，實跑結果（含名單外 ls／echo 被放行的反例）與改寫後的值欄相符，但不滿足 ✅ 的成立條件，理由見末段。驗證方式：派任何 claude -p "<prompt>" --output-format json --allowedTools '<窄名單>'，prompt 要求的動作需用到名單外的工具形狀；讀 stdout JSON 頂層的 permission_denials 陣列，看兩點——(1) 該陣列非空，每筆含 tool_name 與 tool_input；(2) 被拒的呼叫形狀確實不在 --allowedTools 名單內。實跑：#114 第一段派工的 coder session，名單外的 Bash(gh issue comment *) 呼叫被拒，coder 端表現為該指令未執行、回 This command requires approval。受測環境：2026-09-20，Claude Code 2.1.277 headless，執行身分為本機使用者以 Anthropic 訂閱登入，目標 repo AugustusHsu/agent-devflow。為何不是 ✅：(a) 證據為 orchestrator 自派工輸出摘錄，尚無第三者獨立重跑；(b) 自動放行途徑的邊界未定——已觀察：名單外 ls、echo 單獨呼叫過，同一 echo 併入複合指令被拒，ls 指向工作目錄外被拒，重導向到工作目錄內也被拒但錯誤訊息說「只允許寫入工作目錄」；值欄只涵蓋已觀察的形狀，未觀察的形狀不保證。證據：https://github.com/AugustusHsu/agent-devflow/issues/114#issuecomment-5748688404 。原值欄並列的 --permission-mode 與 --dangerously-skip-permissions 依 R7 拆成下兩列）
權限：--permission-mode — --permission-mode <mode> 指定該次執行的權限模式 ⬜ 未測（本 repo 至 544847e 止每次派工都只給 --allowedTools，從未給過此選項，無任何具名來源回報做過。依 R7 與上一列拆開各自標狀態，不共格）
權限：--dangerously-skip-permissions — 持憑證的環境不用 --dangerously-skip-permissions ⬜ 未測（本 repo 至 544847e 止從未給過此選項——「不用」是本 repo 既定做法的宣稱，非實測結果：未驗證此選項的實際行為，也未驗證持憑證環境下省略它的後果。依 R7 與上兩列拆開各自標狀態，不共格）
worktree（I2） coordinator（建）／implementer（不自建） 由 orchestrator 以 git worktree add 建；不用 claude -w ✅ 可用（實測 2026-09-11，驗證方式：orchestrator 在主 checkout 執行 git branch <N>-<slug> origin/main 與 git worktree add ../<repo>.worktrees/<N> <N>-<slug>；啟動 coder 前以 git worktree list 確認輸出含該路徑與分支名，並逐字核對啟動指令不含 -w／--worktree。判定點：worktree 路徑在 repo 目錄之外，且 repo 內不存在 .claude/worktrees/。第三者現在可對任一 repo 重跑此程序。受測環境：2026-09-11，工具為本機 git version 2.43.0 的 worktree 子命令（orchestrator 於主 checkout 執行 git --version），orchestrator 具該 repo 的本機寫入權限，目標 repo AugustusHsu/agent-devflow；證據：issue #4 留言 https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5622810729）
HITL 通道 implementer headless 可用 gh issue comment 留持久紀錄，且 stdout result 可回 BLOCKED: 後正常結束 ✅ 可用（實測 2026-09-20，本格只宣稱通道存在，不宣稱 coder 會自發遵守 L3——後者見下一列。驗證方式：以 headless claude -p … --output-format json 派一個含未決事項的任務，其 --allowedTools 含 Bash(gh issue comment *) 而不含任何 push／PR 工具；檢查三點皆成立——(1) 該 session 的 gh issue comment 成功，留言出現在對應 issue 上、第三者可獨立查得；(2) stdout JSON 的 result 以 BLOCKED: 開頭；(3) 該 session 結束時分支上沒有與該未決事項相關的 commit。第三者現在可用任一 issue 重跑此程序。實跑：#116 第一次派工的 coder 在 worktree 116 遇查證指令被工作目錄範圍擋下（此即未決事項），以 gh issue comment 116 留下逐條結果與停的理由後回 BLOCKED 結束，未就該未決事項自行決定，工作樹保持乾淨（該留言自述「git diff main 為空」）——三點皆成立。該次屬派工 prompt 未涵蓋的情境，但依 R8 不作下一列「自發遵從」的證據（#116 orchestrator 回應留言已記此判定）。受測環境：2026-09-20，Claude Code 2.1.277 headless，gh version 2.97.0、git version 2.43.0（三者皆由實作位當日在同一台主機自跑 claude --version、gh --version、git --version 取得）；執行身分為對 AugustusHsu/agent-devflow 具 write 權限的 gh 登入（留言需要）；目標 repo AugustusHsu/agent-devflow；該次派工的 --allowedTools 具體名單未隨留言留存，能由留言確認的是該 session 未 push、未開 PR、未留下 commit。證據：https://github.com/AugustusHsu/agent-devflow/issues/116#issuecomment-5748771519 。前次受測環境為 2026-09-11、Claude Code 2.1.267 headless、gh 2.97.0、git 2.43.0，證據：issue #4 留言 https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5622863707 ＋ https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5622874599（coder 第一段）；審查者獨立重跑：https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5623667680 。本格受測環境原記 2.1.267，#114 提報本機已升 2.1.277，依 R10 由 #120 重驗更新——2.1.277 上已有上列實跑，狀態維持 ✅）
HITL（L3 遵從） implementer 遇未決事項會自發 issue 留言後停（非 prompt 明令） ⬜ 未測（派工 prompt 若明令「留言後停」，依 R8 只證服從指令、不證自發遵從；需設計不含該指令的測試）
審查用法（R1） reviewer 於乾淨的 /tmp checkout（切到待審 HEAD sha）執行 claude -p "$(cat <prompt.txt>)" --output-format json --max-turns <N> --allowedTools '<list>'；stdout 為單一 JSON，其 result 即 verdict 全文，由 orchestrator 貼到 PR ✅ 可用（實測 2026-09-21，升自 📝；既有 📝 記載原文保留於後段。✅ 成立條件：原「為何不是 ✅」兩點皆補齊——(i) 在第二個 repo 由不同 PR 以值欄宣稱的路徑（result 由 orchestrator 貼到 PR）重跑，三點再現；(ii) 該次 --max-turns／--allowedTools 完整值隨證據留在 forge 留言。實跑：消費者 repo AugustusHsu/devflow-e2e PR #6（head e86a486），git clone --shared 到 /tmp 後 git checkout e86a486，prompt 由 templates/review-prompt.md 填空，指令 claude -p "$(cat /tmp/e2e-rv6.txt)" --output-format json --version),Bash(claude --version),Bash(gh pr view *),Bash(gh pr diff *),Bash(gh issue view *)'（不含 gh pr review，故貼出者只能是 orchestrator）：(1) stdout 為單一 JSON，subtype: success、38 turns；(2) result 13 行：第 1 行為模板輸出格式的 `` 圍欄、第 2 行VERDICT: APPROVE、第 3 行HEAD: e86a486…，含 AC-1～AC-5、Counterexample、Write scope、G5、Verification；(3) orchestratorgh pr review 6 --comment --body-file貼出 → review id5262731415，gh api 全文」，本次成立。受測環境：2026-09-21，Claude Code2.1.277（當日claude --version）；執行身分為本機使用者以 Anthropic 訂閱登入；目標 repo 私有AugustusHsu/devflow-e2e。證據：https://github.com/AugustusHsu/devflow-e2e/issues/5#issuecomment-5754798402（三點原文、review id、比對結果）、https://github.com/AugustusHsu/devflow-e2e/pull/6。—— 以下為原📝記載：驗證方式：把待審 PR 的 HEAD sha checkout 到一個/tmp目錄，審查 prompt 寫在，以值欄的指令啟動；看三點——(1) stdout 為單一 JSON 物件；(2) 其result為 verdict 全文（VERDICT:開頭、含阻擋項與非阻擋觀察）；(3) 該result與 orchestrator 貼到 PR 上的 verdict 逐項一致。實跑：Claude 於 PR #111 首次擔任 reviewer，一輪 APPROVE，verdict 內文自載HEAD: b1bc0eb，含逐句實測四句與六項非阻擋觀察，第三者可與該留言比對。受測環境：2026-09-20，Claude Code2.1.277（實作位當日在同一台主機執行claude --version所得，stdout 為2.1.277 (Claude Code)；本表本機節「版本」格已於 #114 verdict https://github.com/AugustusHsu/agent-devflow/pull/111#pullrequestreview-5260050219 。原值欄並列的gh pr diff | claude -p依R7` 拆成下一列）
審查用法：pipe diff（R1） reviewer gh pr diff <N> | claude -p "<review-prompt>"——以 stdin 餵 diff、不開 checkout ⬜ 未測（本 repo 至 6f3656d 止從未以此形式派過審查，無任何具名來源回報做過。依 R7 與上一列拆開各自標狀態，不共格，見 #112 AC-4）
交接（--resume） implementer（context 延續）／coordinator（重派） --output-format json 回 session_id，可 --resume <session_id> 續同一 session ✅ 可用（實測 2026-09-20，驗證方式：(1) 執行 claude -p "<任意 prompt>" --output-format json，記下 stdout JSON 的 session_id；(2) 在同一 worktree 以 claude -p "<後續 prompt>" --resume <該 session_id> --output-format json 再啟動一次；(3) 比對第二次 stdout 的 session_id 與第一次相同，且第二次的回應以第一次的 context 為前提（不需重述背景即可續做）。此程序不依賴特定 prompt，第三者現在可獨立重跑。實跑：#120 的 coder 兩段派工——第一段更新本表第 9 行（headless 執行）與第 15 行（HITL 通道）兩格的受測環境並 commit 2de8506；第二段由 orchestrator 在同一 worktree 以 claude -p --resume <第一段的 session_id> 接回，該段 prompt 只交辦「更新本列受測環境、證據引 issue #120」，未告知第一段改的是哪兩格、也未給第一段的 commit sha，該 session 仍寫得出兩者，並在此基礎上續填本列（本列即其產物）——此點與下一列 --continue 格不同：該次第二段 prompt 另行重述了第一段的內容，依 R8 證據面較窄，本次未重述。兩段的 session_id 是否相同由 orchestrator 比對後貼於證據 URL——coder 端讀不到自己的 session_id（與下一列所記為同一限制）。受測環境：2026-09-20，Claude Code 2.1.277 headless（實作位當日在同一台主機執行 claude --version，stdout 為 2.1.277 (Claude Code)，與本表本機節「版本」格一致），同一 worktree 路徑 agent-devflow.worktrees/120；第二次須由同一 OS 使用者執行（--resume 讀取該使用者 ~/.claude/ 下的 session 紀錄，換身分或清除該目錄即無法續接）；執行身分為本機使用者以 Anthropic 訂閱登入；目標 repo AugustusHsu/agent-devflow；證據：https://github.com/AugustusHsu/agent-devflow/issues/120 。前次受測環境為 2026-09-11、Claude Code 2.1.267 headless，證據：issue #4 留言 https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5622874599 與 https://github.com/AugustusHsu/agent-devflow/issues/4#issuecomment-5623153788，兩者 session_id 相同。本格受測環境原記 2.1.267，#114 提報本機已升 2.1.277，依 R10 由 #120 重驗更新——本單第二段即 2.1.277 上的實跑，狀態維持 ✅）
交接（--continue） implementer（context 延續）／coordinator（重派） 同目錄 --continue 📝 已宣稱（R9 子類「驗證未達 ✅」：本格附有第三者現在能執行的驗證方式，實跑結果與值欄宣稱相符，但不滿足 ✅ 的成立條件，理由見末段。驗證方式：(1) 在某 worktree 以 claude -p "<第一段 prompt>" --output-format json 派一段會留下可指認產物（例如 commit）的工作，記下 stdout JSON 的 session_id；(2) 同一目錄、同一 OS 使用者，以 claude -p "<第二段 prompt>" --continue --output-format json 接回，第二段 prompt 不重述第一段的任務內容；(3) 比對三點——第二段 stdout 的 session_id 與第一段相同、第二段能在未被告知的情況下說出第一段做了什麼、第二段的產物接續第一段而非重做。不加 --resume <id>：本格要驗的正是 --continue 取同目錄最新 session 這個形式（與上一列的 --resume 拆開，依 R7 各自標狀態）。實跑：#114 的 coder 兩段派工——第一段改權限格與版本格並 commit 2eeff4a；第二段由 orchestrator 在同一 worktree 以 claude -p --continue 接回，該 session 未被告知第一段改的是哪兩格仍答得出，並在此基礎上續填本列（本列即其產物）；兩段的 session_id 是否相同由 orchestrator 比對後貼於證據 URL——coder 端讀不到自己的 session_id，第一段嘗試讀 ~/.claude/projects/ 被工作目錄範圍擋下。受測環境：2026-09-20，Claude Code 2.1.277 headless，同一 worktree 路徑 agent-devflow.worktrees/114；須由同一 OS 使用者執行（--continue 讀取該使用者 ~/.claude/ 下對應該目錄的 session 紀錄，換身分或清除該目錄即無法續接）；執行身分為本機使用者以 Anthropic 訂閱登入；目標 repo AugustusHsu/agent-devflow。為何不是 ✅：(a) 驗證由 orchestrator 執行並回報，尚無第三者獨立重跑；(b) 本次第二段 prompt 除交接事實外，另行告知了第一段的 commit sha 並重述了本格該寫的內容，依 R8 這部分的「知道第一段做了什麼」分不出是 context 延續還是 prompt 所給，未被 prompt 覆蓋而仍答對的只有「第一段改的是哪兩格」一項，證據面窄於本格驗證方式第 (3) 點所要求者。證據：https://github.com/AugustusHsu/agent-devflow/issues/114 ）
