seat: coordinator（協調位）¶

職位定義。只寫這個位要做什麼、受哪些規則約束、填它的人或工具要會什麼。不指定填哪個工具，也不記工具的指令；前者是綁定、後者住對照表。

職責¶

確認範圍、固定 G／T、建 worktree、啟動實作位、向人提問、驗證交付、收尾。

  • 開工前讀 stage，只套用生效的節（ST0、ST1、ST2、ST3）；保護節不依 stage（ST5）。
  • 確認範圍：派工前 issue 具備 L1 各欄，「未決事項」為空；規則變更的 issue 記錄問題與人的裁決（G2）。第 12 節生效時逐項確認 P1（外部資源的範圍依 P2）並寫進 issue（P4）。
  • 固定 G／T：寫進 issue 與 PR（第 0 節、G1）。新版規則的啟用點是任務／session 邊界，進行中的任務續用舊 G；新版修補安全缺陷時明確暫停受影響任務並遷移（G3）。
  • 任務推導（第 2 節生效時）：由規格 diff ＋ 既有實作 ＋ 影響分析推導，不由版本位數推導（S3）；不為湊數發明任務（S4）。
  • 建 worktree：從最新 main 建分支與 worktree 於 ../<repo>.worktrees/<N>（I2、L2）。
  • 啟動實作位：交付 issue、G、T、worktree 路徑、驗證指令（L2）；同一時間一張 issue 只有一個實作者（I1）。
  • 向人提問：實作位停下時，把問題帶給裁決位，答案寫回 issue，再重派（L3）。
  • 驗證交付：PR 形狀（L4；代行時進 main 仍經 PR、以 merge commit 合入，I3）；之後依序審查 → 合併 → 收尾（L5）。派審並依異廠建議選填充工具（R1、R2）；把 verdict 帶回 forge（R5）；head 變更後重派審（R3）；候選分支中的入口檔、skill、CI 變更不當本次治理依據（G5）。合併前提逐項驗（M1），合併者依 M2；main 前進時 merge main、重測、重審，驗證對象是最終整合候選（M3、M4）。
  • 收尾：C1 七步依序、C2 關 issue 並讀回、C3 只清本任務資源、C4。
  • 失敗與退版：實作兩輪無進展升級到人（F1）；規格錯或出現新依賴時暫停受影響任務、無關任務繼續（F2）；forge 回錯或逾時先讀回再決定（F3）；合併成功但收尾失敗記 cleanup pending、只補收尾（F4）；撤回壞實作以 revert PR 走 I3（F5）；已部署或涉及 migration 時另行處置產物、配置與資料（F6）；取消任務而分支已有 commit，先問人（L6）。
  • Bypass 的執行（授權歸裁決位）：直推的 commit 依 B2 標示並引用 bypass issue；forge 不可用時先留本機紀錄，恢復後補 issue（B3）。
  • 合併序列化，後合者適應（P3）。
  • 中斷與重派：確認舊填充者已停、工作區狀態讀回後才重派。

產出物¶

issue 上的 G／T 與裁決寫回、分支、worktree、（代行時）push 與 PR、verdict 的 forge 紀錄、收尾結果。

禁止¶

  • 不持有工單的第二份拷貝（I4）。
  • 不放行未達 M1 的合併；只在 devflow.yml 的 merge 允許且有機械 guard 能驗 M1 時才按（M2）。
  • 不自行 bypass（F3）；不強制刪除未合入的分支（C1）；不清其他任務的資源（C3）；分支已有 commit 不逕自刪（L6）。
  • 不代簽 verdict——審查由審查位以全新 context 做（R1）。
  • 超過 20 KB 的檔案不整份載入（D4）。

context 語意¶

長駐：跨任務持續。規則版本的切換點是任務／session 邊界（G3），此位在邊界重新載入 G。

填充者¶

工具或人。沒有工具填此位時，各步由人親自執行；換填充者不改變 issue、分支、worktree、PR 的形狀（I6）。

填充者須具備的能力¶

  • 管理主 checkout、分支與 worktree：建立、列出、移除；判定 commit 間的祖先關係；讀取與刪除遠端分支——C1 七步所需的全部操作。
  • 操作 forge：開、讀、留言、關 issue；開 PR、讀回 PR 狀態與 CI 結果（L1、L4、C2、F3）。
  • 啟動與停止實作位的填充者，並能判定它已停（C1 第 (2) 步）。
  • 啟動審查位的填充者，餵入 templates/review-prompt.md（R1）。
  • 向人提問並等答案（L3）；持久紀錄在 issue，提問通道只是通道。
  • 長駐，並在任務邊界重新載入 G（G3）。
